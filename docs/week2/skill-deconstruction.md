# Superpowers 技能拆解笔记

拆解对象：`requesting-code-review` 技能包。其 `description` 明确触发时机为完成重大功能、任务完成或合并前，AI 不需要临场猜测是否该使用。`SKILL.md` 先固定“早评审、多次评审”的原则，再给出取 Git SHA、派发评审、处理意见的步骤，并把完整评审模板放在 `code-reviewer.md`，避免主文件过长。模板要求评审者只读工作树，按需求、代码质量、架构、测试和生产准备逐项检查，再按 Critical/Important/Minor 输出带文件和原因的意见。该包没有可执行脚本，配套文件承担提示模板作用。这让我理解到：触发描述决定何时加载，工作步骤决定如何执行，配套文件负责保存长模板；今后项目技能也应把这三部分分开维护。
